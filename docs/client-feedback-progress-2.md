# 고객 피드백 반영 진행상황 (2차 시연 회의)

> 출처: 2차 시연 회의(담당자 검토). 1차는 [client-feedback-progress.md](./client-feedback-progress.md).
> 상태: ⬜ 대기 · 🟡 진행중 · ✅ 완료 · ⏸ 보류(확인 필요)

## 확정된 결정 (회의 후 확인)

- **분과 추가 주체**: 담당자·관리자 **둘 다** 가능.
- **비밀번호 표시**: 평문 노출 대신 **재발급 방식**. 실제 비밀번호는 해시라 되돌릴 수 없음 →
  "정보 변경" 안에서 **재발급**해 새 임시 비밀번호를 확인. (임시 비밀번호가 아직 유효한 계정은 그 값 표시 가능)
- **평가 항목**: 클라이언트가 실제 항목을 구성함 → 착수 가능.

## 🗂 화면별 피드백

### ① 담당자 관리 (관리자)
- [ ] 아이디 옆 **비밀번호 열**(재발급 방식, C4)
- [ ] 열: 이름 · 아이디 · 비밀번호 · 연락처 · 참여 사업 · **참여 중인 분과**(신규, 여러 개 가능)
- [ ] 새 담당자 등록 폼에 **비밀번호 필드**(생성 시 자동 세팅 확인)
- [ ] 삭제·수정 → **체크박스 + 하단 "담당자 정보 변경"**(C1·C2·C3)

### ② 사업 관리 (관리자)
- [ ] 참여 담당자 재세팅 제거 → 담당자 관리 값 그대로, 맨 아래 **"담당자 현황"**
- [ ] "사업 담당자 설정" 화면 축소(**3명만+스크롤** 또는 세로 배치)
- [ ] **"사업 담당자 설정" → "분과 설정"** 개명
- [ ] **사업 삭제 버튼 제거** → 테이블 맨 아래 **"사업 정보 변경"**(수정/삭제) (E2 지침)
- [ ] 세팅 후 **분과 화면으로 리다이렉트 금지**(사업 관리에 머무름) — E2

### ③ 평가 실시간 모니터링 (관리자)
- [ ] 제목 "자세히 보기" → **"상세 평가 진행 상황"** + 자세히 보기 버튼(C5)
- [ ] 삭제 → 체크박스(C1) · 가져오기 불필요 · 앞/뒤 이동 통일(C7)

### ④ 평가 항목 (관리자)
- [x] 양식 다운로드 = 헤더만 있는 빈 양식 ✅ (1차에서 완료)
- [ ] 양식 **엑셀 + 한글 두 버전** 제공
- [ ] "엑셀 내보내기" → **"내보내기"**(C6)

### ⑤ 평가 대상 관리 (관리자)
- [ ] "점수 보기" → **통합 점수 + 자세히 보기**(C5)
- [ ] "평가 대상(수)" → **"평가 대상 현황"**, **"○개 기업"** 표기, 자세히 보기 작게
- [ ] 승인/반려 상태 **가운데 정렬**
- [ ] **내보내기만**(C6) · 가져오기 버튼 위치 이동 + 양식 제공(한글 불가 시 "엑셀 가져오기")
- [ ] "관리" → 체크박스 + **"평가 대상 정보 변경"**(수정·삭제) (C1·C3)

### ⑥ 평가위원 관리/선정 (관리자)
- [ ] 삭제된 분과가 계속 뜸 → **없으면 "미정" 표시** (오류 E1)
- [ ] 위원 삭제 → 체크박스 + **"위원 정보 변경"**(정보변경·재발급·삭제) (C1·C3)
- [ ] 열에 **소속 · 직급 · 연락처** 추가
- [ ] "자세히 보기" → **"평가위원장 종합 의견"** + 자세히 보기(C5)
- [ ] 위원 제출 주체(담당자?) — ⏸ 나중에 확인(사용자 보류)

### ⑦ 담당자 화면
- [ ] 배정받은 사업만 표시
- [ ] 분과 추가(담당자·관리자 둘 다) — A유형/B유형 등
- [ ] **평가 항목 수 컬럼 제거**(1차 합의)
- [ ] 평가 항목 화면 **앞으로 이동(화살표)**(C7)
- [ ] 담당자용 평가 항목 **양식 제공**

### ⑧ 평가위원 화면 (위원/위원장)
- [ ] 배정 분과만 · 위원은 본인 평가 정보만(위원장 현행 유지)
- [ ] 평가위원 배정 목록 **위원장 맨 앞**
- [ ] 블라인드 제거 가능
- [ ] **"계정 삭제" 버튼 제거** → 배정 해제까지만, 해제도 체크박스+정보 수정(C1·C3)

> **E1 원인**: `EvaluationSession.project` FK가 `onDelete: SetNull`이라, 사업을 삭제해도 분과가
> 삭제되지 않고 `projectId=null` 고아로 남아 평가위원 홈·시트·위원장 화면·관리 칩에 계속 노출됨.
> (현재 DB에 고아 분과 13개 — "시연 분과" 포함)
>
> **수정**:
> - `deleteProject`가 사업의 모든 분과를 `purgeSession`으로 정리 후 삭제 → 향후 고아 미발생.
> - 평가위원 홈(`getHomeData`)·시트(`getSheetData`)·위원장(`getChairSubjectData`)이 `projectId=null` 분과 제외(방어).
> - 관리자 평가위원 관리 배정 칩에서 고아 분과 제외, 빈 경우 라벨 "배정 없음"→**"미정"**.
> - 검증: wiwon1 홈 0개(고아 숨김), 칩은 유효 분과만.
>
> ⏳ **남은 정리(선택)**: 기존 고아 분과 13개 실제 삭제는 파괴적(공유 DB)이라 사용자 확인 대기.
