# 전 과정 시나리오 — 사업 생성부터 분과 마감까지 (가드 검증 포함)

> 데모 리허설·QA용 종합 시나리오. 정상 흐름(Phase 0~8)을 순서대로 진행하면서,
> 중간중간 **🔒 가드 체크**로 비정상 흐름이 서버에서 차단되는지 함께 확인한다.
>
> 표기: **관리자**=MASTER(`admin` / `admin1234`) · **담당자**=SECRETARY · **위원/위원장**=EVALUATOR
> 위원·위원장 로그인은 `/demo-login`(분과별 평가위원 로그인)이 가장 빠르다.

## 예시 데이터 (이 문서 기준)

| 구분 | 값 |
|---|---|
| 사업 | `2027년 시범지역 신규사업 평가` (기간 임의, 만점 100) |
| 분과 | `제1분과` |
| 담당자 | `김담당` / `KDD123` / 연락처 `010-1111-2222` → 비밀번호 `2222` |
| 평가위원 | `이위원`/`LWW123`/`010-2222-3333`, `박위원`/`PWW123`/`010-3333-4444`, `최위원장`/`CWJ123`/`010-4444-5555` (위원장) |
| 평가대상(기업) | `(주)한빛테크`, `(주)미래소프트`, `(주)그린에너지` |

## Phase 0 — 계정 준비 (관리자)

| # | 화면 | 행동 | 기대 결과 |
|---|---|---|---|
| 0-1 | `/login` | 관리자 데모 계정으로 로그인 | 관리자 홈 진입 |
| 0-2 | 담당자 관리 → `+ 담당자 추가` | 김담당 정보 입력(이름·아이디·연락처) | 목록에 추가, **비밀번호 = 연락처 끝 4자리**(2222) 표시 |
| 0-3 | 평가위원 관리 → `+ 평가위원 추가` | 이위원·박위원·최위원장 3명 등록(소속·직급 선택 입력) | 목록에 추가, 비밀번호 = 연락처 끝 4자리. 참여 사업 `사업 설정`, 배정 분과 `분과 설정` 밑줄 링크 표시(아직 미배정) |

> 대량 등록은 `양식 다운로드` → 엑셀 작성 → `엑셀 업로드`(또는 표 복사 후 붙여넣기)로도 가능.
> 평가위원 양식에는 비밀번호 열이 없다(연락처 끝 4자리 자동 발급).

**🔒 가드 체크 A — 위원 배정 전 상태 표시**
- 평가위원 관리에서 방금 등록한 위원의 참여 사업/배정 분과가 비어 있으면 ‘참여 없음/미정’ 대신 **`사업 설정`/`분과 설정` 밑줄 텍스트**가 떠야 한다. `분과 설정`을 눌렀을 때 참여 사업이 없으면 “먼저 ‘사업 설정’에서 참여 사업을 선택하세요” 안내가 떠야 한다.

## Phase 1 — 사업·분과 생성 + 담당자 배정 (관리자)

| # | 화면 | 행동 | 기대 결과 |
|---|---|---|---|
| 1-1 | 사업 관리 | `+ 사업 추가` → 사업명·기간·만점(100) 입력 | 사업 생성 |
| 1-2 | 사업 상세(분과 설정) | `+ 분과 추가` → `제1분과`, 담당자 김담당 선택 | 분과 생성(상태 **준비**), 담당자 열에 김담당 |
| 1-3 | 사업 상세 하단 `담당자 현황` | 확인 | 김담당 행에 **참여 사업**·담당 분과 칩 표시 |

> 담당자 배정은 ①분과 생성 시 선택, ②분과 표의 담당자 셀, ③담당자 관리의 `분과 설정`/정보 변경 — 어느 경로든 동일하게 동작.

## Phase 2 — 평가항목 (관리자 작성 → 담당자 확인)

| # | 역할 | 화면 | 행동 | 기대 결과 |
|---|---|---|---|---|
| 2-1 | 관리자 | 사업 → 평가 항목 | `가져오기`로 엑셀 업로드 또는 표 붙여넣기 (평가항목/세부항목/평가지표/배점 4열) | 미리보기가 같은 평가항목·세부항목을 **병합(rowspan)** 해 보여줌 |
| 2-2 | 관리자 | 〃 | 세부항목 하나에 지표 여러 개 + 배점이 한 번만(병합) 적힌 양식 사용 | **통합 배점**으로 인식(각 지표 배점이 아니라 세부항목 배점 1개, ‘통합 배점’ 배지) |
| 2-3 | 담당자 | 분과 → 평가 항목 | 내용 확인 | 사업 공통 항목이 그대로 보임(수정 불가) |

**🔒 가드 체크 B — 통합배점 인식**
- 병합 배점이 `30/30/30`처럼 각 행에 복제된 형태로 붙여넣어도 합계 90이 아니라 **통합배점 30**으로 잡혀야 한다.

## Phase 3 — 평가대상(기업) 등록 (담당자 작성 → 관리자 승인)

| # | 역할 | 화면 | 행동 | 기대 결과 |
|---|---|---|---|---|
| 3-1 | 담당자 | 로그인(`KDD123`/`2222`) → 분과 → 평가 대상 | 기업 3곳 신규 등록(지역·연구책임자 필수) | 표에 3행 추가(상태 열 없음) |
| 3-2 | 담당자 | 〃 행 `관리` | 과제 서류(PDF) 업로드 | 문서 목록에 추가, `/viewer`로 열람 |
| 3-3 | 담당자 | 〃 상단 배너 | **제출** | ‘제출됨 · 관리자 검토 대기’ |
| 3-4 | 관리자 | 분과 → 평가 대상 | 확인 후 **승인** | ‘승인됨’ |

**🔒 가드 체크 C — 평가대상 워크플로**
- (관리자) 담당자가 **제출하기 전**에는 평가 대상 목록이 보이지 않아야 한다(배너만).
- (담당자) **제출 후**에는 추가·수정·삭제 불가 안내가 떠야 한다(제출 취소하면 다시 가능).
- (관리자) 서류 업로드/삭제는 제출 상태와 무관하게 가능해야 한다(마감 전).

## Phase 4 — 평가위원 배정 (관리자) → 위원장 지정 (담당자)

| # | 역할 | 화면 | 행동 | 기대 결과 |
|---|---|---|---|---|
| 4-1 | 관리자 | 평가위원 관리 | 위원 3명 각각 `사업 설정`→시범사업 체크, `분과 설정`→제1분과 체크 (또는 정보 변경 모달에서 한 번에) | 배정 분과 칩 `제1분과` 표시 |
| 4-2 | 담당자 | 분과 → 평가위원 현황 | 배정 확인 후 **제출** | ‘제출됨’ |
| 4-3 | 관리자 | 〃 | **승인** | 배정 확정(APPROVED) |
| 4-4 | 담당자 | 〃 위원장 지정 | 최위원장을 위원장으로 지정 | 이름 옆 ‘위원장’ 배지 |

**🔒 가드 체크 D — 배정 권한 분리**
- 담당자 화면에는 **평가위원 배정(추가) UI가 없어야** 한다(위원장 지정만). 배정은 관리자 전용.
- `분과 설정`에서 참여 사업에 없는 사업의 분과는 목록에 나오지 않아야 한다.

## Phase 5 — 분과 진행 시작 + 위원 채점

| # | 역할 | 화면 | 행동 | 기대 결과 |
|---|---|---|---|---|
| 5-1 | 담당자/관리자 | 분과 → 실시간 진행 상황 | 상태를 **준비 → 진행중** 전환 | 위원 로그인 시 평가 가능 |
| 5-2 | 위원(이위원) | `/login`(아이디/연락처 끝4자리) 또는 `/demo-login` | 대상 선택 → 항목별 점수 + 평가항목별 의견 + **평가위원 종합의견** 입력 → `제출 전 확인` → 서명 → 제출 | 대상별 제출 완료, 진행 스텝 ‘제출’ ✓ |
| 5-3 | 위원(박위원) | 〃 | 3개 대상 모두 제출 | 〃 |
| 5-4 | 위원장(최위원장) | 〃 | 3개 대상 **점수 입력 + 임시 저장**(제출은 아직 안 함) | 평가표 하단에 ‘위원장 종합의견’ 칸 노출 |

**🔒 가드 체크 E — 채점 단계**
- 모든 항목을 입력하기 전에는 위원의 `제출 전 확인` 버튼이 비활성이어야 한다.
- 제출한 위원이 다시 열면 **읽기 전용**(“이미 제출/승인되어 수정할 수 없습니다”)이어야 한다.
- 담당자 ‘실시간 진행 상황’의 진행률/자세히 보기(→평가 의견서 탭 이동)가 갱신되어야 한다.

## Phase 6 — 위원장 검토 (확인 + 위원장 종합의견 + 본인 제출)

| # | 화면 | 행동 | 기대 결과 |
|---|---|---|---|
| 6-1 | 평가표 → `위원별 평가 · 종합의견 →` | 대상별로 각 위원 행의 **검토완료** 클릭(확인 모달 ‘예’) | ‘확인 완료’로 변경 |
| 6-2 | 〃 | 위원장 종합의견 작성 → **제출**(서명) | ‘제출됨’, 진행 스텝 4(담당자 검토)로 이동, 표의 본인 행도 즉시 ‘제출’ |

**🔒 가드 체크 F — 위원장 단계**
- **미제출 위원**의 `검토완료` 버튼은 비활성(“위원이 제출해야 확인할 수 있습니다”)이어야 한다.
- **종합의견이 비어 있으면** 제출 불가(“종합의견을 작성한 뒤 제출할 수 있습니다”)여야 한다.

---

## Phase 7 — 담당자 검토 완료 → 집계 → 관리자 승인

> ⭐ 이 구간이 핵심 가드 구간. **순서를 일부러 어겨서** 차단을 먼저 확인한다.

**🔒 가드 체크 G — 위원장 검토 전 담당자 검토 완료 차단** *(6단계보다 먼저 시도)*
1. 위원장 검토가 끝나기 **전** 담당자로 분과 → 평가 의견서 진입.
2. 노란 라벨 확인: “**위원장 검토가 끝나야 검토 완료할 수 있습니다.**” + 사유(미확인 n건 / 위원장 본인 평가 제출 n건 / 위원장 종합의견 n건).
3. 그래도 `검토 완료` → 확인 모달 확정 → **상태가 ‘검토중’ 그대로**(서버 차단).

**🔒 가드 체크 H — 검토 전 집계 결과**
- 담당자/관리자 집계 결과 상단에 “**평가 의견서**에서 검토를 완료하면 집계 결과에 점수가 표시됩니다. (현재 검토 전)” 라벨.
- 항목 점수·**최종·등급 모두 `–`** (0.00/D로 보이면 안 됨).
- 하단 `제출 완료` 클릭 → 확인 모달 → “**평가 의견서 검토 완료 후 제출할 수 있습니다.**” 에러.

정상 흐름(Phase 6 완료 후):

| # | 역할 | 화면 | 행동 | 기대 결과 |
|---|---|---|---|---|
| 7-1 | 담당자 | 분과 → 평가 의견서 | 차단 라벨이 사라졌는지 확인 → `검토 완료`(확인 모달) | ‘검토 완료 · 관리자 승인 대기’ |
| 7-2 | 담당자 | 집계 결과 | 확인 | **점수·순위·등급·선정 결과 표시** |
| 7-3 | 관리자 | 분과 → 평가 의견서 | `승인`(확인 모달) | ‘승인됨’ |

**🔒 가드 체크 I — 검토 시작 후 잠금**
- (위원) 검토 완료 후 미제출 위원이 제출 시도 → “**담당자 검토가 진행 중이라 제출할 수 없습니다.**”
- (위원장) 위원장 화면이 읽기 전용으로 잠기고, `검토완료`(확인) 변경도 차단.
- (담당자) `검토 취소`를 누르면 위 잠금이 풀리고 다시 제출 가능해야 한다.

**🔒 가드 체크 J — 반려 흐름** *(선택)*
- 관리자가 `반려`(사유 입력) → 담당자 화면에 반려 사유 표시, 상태 ‘반려됨’ → 담당자 재검토 후 `다시 검토 완료`.

---

## Phase 8 — 분과 제출 완료 → 관리자 검토 완료(마감)

**🔒 가드 체크 K — 승인 전 마감 차단** *(7-3보다 먼저 시도)*
- 관리자 집계 결과 하단에 “⚠ **평가 의견서를 승인해야 분과 검토를 완료할 수 있습니다.**” 라벨.
- `검토 완료` 클릭 → 확인 모달 확정 → **마감되지 않음**(서버 차단).

정상 흐름:

| # | 역할 | 화면 | 행동 | 기대 결과 |
|---|---|---|---|---|
| 8-1 | 담당자 | 집계 결과 하단 | `제출 완료`(확인 모달) | ‘제출 완료됨’ |
| 8-2 | 관리자 | 집계 결과 하단 | `검토 완료`(확인 모달) | **‘검토 완료됨’ — 분과 마감(CLOSED)**, 점수 잠김 |

**🔒 가드 체크 L — 마감 후 잠금**
- 담당자: 평가 대상/위원장 지정 등 수정 UI가 잠겨야 한다(“마감된 분과는 …”).
- 관리자: 마감된 분과의 평가 의견서 `반려`가 동작하지 않아야 한다(상태 유지).
- 담당자 분과 제출의 `제출 취소`도 불가(‘검토 완료됨’ 표시).
